Working flow §10

Page load, Refresh scrape, and manual entry, step by step.

sequenceDiagram
  actor User
  participant FE as React
  participant BE as FastAPI
  participant SC as scraper.py
  participant TZ as tz_convert.py
  participant DB as SQLite
  participant PB as p-bandai.jp
  Note over FE,DB: Page load
  User->>FE: open localhost:3000
  FE->>BE: GET /api/items
  BE->>DB: SELECT all
  DB-->>BE: rows
  BE-->>FE: items
  FE-->>User: card grid
  Note over FE,PB: Refresh (Phase 2, R4)
  User->>FE: click Refresh
  FE->>BE: POST /api/scrape
  BE->>SC: scrape()
  SC->>PB: GET listing page
  PB-->>SC: HTML
  SC-->>BE: items or error
  BE->>TZ: JST to local
  BE->>DB: upsert
  BE-->>FE: count + errors
  FE-->>User: toast + reload grid
  Note over FE,DB: Manual entry (Phase 1, R5)
  User->>FE: fill form, Save
  FE->>BE: POST /api/items
  BE->>TZ: JST to local
  BE->>DB: INSERT
  BE-->>FE: 201 item
  FE-->>User: toast + reload grid

Logic flow §11

Every branch the app can take.

flowchart TD
  A[Open localhost:3000] --> B[GET /api/items]
  B --> C{HTTP OK?}
  C -->|No| D[Error: API not running]
  C -->|Yes| E{Any items?}
  E -->|0| F[Empty state]
  E -->|1+| G[Card grid R1 R2 R3]
  G --> H{User action}
  H -->|Order| I[p-bandai.jp in new tab]
  H -->|Refresh R4| J[POST /api/scrape]
  J --> K{Scrape ok?}
  K -->|Yes| L[Toast count or 0-item warning]
  K -->|No| M[Toast error, keep items]
  H -->|Add Item R5| N[Entry form]
  N --> O{Valid?}
  O -->|No| P[Inline field errors]
  O -->|Yes| Q[POST /api/items]
  Q --> R[Toast success]
  L --> G
  M --> G
  R --> G
